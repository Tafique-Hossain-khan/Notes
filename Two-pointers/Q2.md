# Squares of a Sorted Array

**Pattern:** Two Pointer (Merge-style) · **Difficulty:** Easy · **LeetCode:** Squares of a Sorted Array

---

## Problem
Given a **sorted** array (may include negatives), return an array of squares, **also sorted**, in O(n) — no sort function allowed.

---

## Recognition Signals
- [x] Array or Linked List? → Array
- [x] Sorted / sortable? → Given sorted
- [x] Keyword match? → Not explicit, but "sorted output required + no re-sort" implies Two Pointer
- [x] Space constraint? → Follow-up asks for O(n), ruling out sort()

---

## Core Idea
Squaring flips the order of the **negative** portion (most negative → largest square) but preserves the order of the **positive** portion. Split into two sorted sub-arrays (reverse the negative one after squaring), then this becomes a **Merge Two Sorted Arrays** problem — solved with two pointers.

**Sub-concept — Merge Two Sorted Arrays:** compare front elements of both arrays, take the smaller, advance that pointer, repeat; when one array empties, append the rest of the other (already sorted).

---

## Key Notes
- **Split before squaring, never after.** Squaring erases the sign, so if you square first you lose the information needed to separate negatives from positives.
- **Why negative-squared is descending:** the most negative number (smallest value) has the largest magnitude → becomes the largest square. The least negative (closest to 0) becomes the smallest square. So reversing is mandatory, not optional.
- **All 3 branches must be handled explicitly** — all-positive, all-negative, mixed — because the merge step only makes sense when both sub-arrays are non-empty; skipping this check breaks the all-positive/all-negative cases.
- **Complexity rule (same as other problems):** splitting O(n) + squaring O(n) + reversing O(n) + merging O(n) → all independent linear steps, so total stays O(n), not additive blow-up.
- In code, squaring + reversing the negative array can be written as a single expression (e.g., `[x*x for x in reversed(neg)]` in Python) — a style/optimization detail, not a logic change.

## Approach Comparison

| Approach | Time | Space | Verdict |
|---|---|---|---|
| Square all + sort() | O(n log n) | O(n) | Fails follow-up |
| Split + Square + Reverse + Merge (Two Pointer) ⭐ | O(n) | O(n) | Meets follow-up |

---

## Algorithm Steps
1. Split `arr` into `neg[]` (values < 0) and `pos[]` (values ≥ 0).
2. **Case: neg is empty** → square `pos`, return.
3. **Case: pos is empty** → square `neg`, reverse, return.
4. **Case: both exist:**
   - Square `neg`, then reverse it (fixes descending → ascending).
   - Square `pos` (already ascending).
   - Merge `neg` and `pos` using two pointers (see merge steps below).
5. Merge: `i=0, j=0, id=0`; while both in bounds, compare `neg[i]` vs `pos[j]`, place smaller into `result[id]`, advance that pointer and `id`.
6. After loop, append any leftover elements from whichever array still has some.
7. Return `result`.

---

## Pseudocode
```
function sortedSquares(arr):
    neg, pos = [], []
    for x in arr:
        if x < 0: neg.append(x) else: pos.append(x)

    if len(neg) == 0: return [x*x for x in pos]
    if len(pos) == 0: return reverse([x*x for x in neg])

    neg = reverse([x*x for x in neg])
    pos = [x*x for x in pos]

    i, j, id = 0, 0, 0
    result = new array(len(neg) + len(pos))
    while i < len(neg) and j < len(pos):
        if neg[i] <= pos[j]:
            result[id] = neg[i]; i++; id++
        else:
            result[id] = pos[j]; j++; id++
    while i < len(neg): result[id] = neg[i]; i++; id++
    while j < len(pos): result[id] = pos[j]; j++; id++
    return result
```

## Dry Run
`arr = [-4, -1, 0, 3, 10]`

| Step | Value |
|---|---|
| Split | neg=[-4,-1], pos=[0,3,10] |
| Square neg, reverse | [1, 16] |
| Square pos | [0, 9, 100] |
| Merge | 0,1,9,16,100 |

**Result:** `[0, 1, 9, 16, 100]`

## Gotchas / Edge Cases
- Handle 3 cases explicitly: all-positive, all-negative, mixed.
- Negative-squared array is sorted **descending** — must reverse before merging.
- Don't square before splitting — squaring first destroys the negative/positive sign info needed to split correctly.
- Same merge-loop termination rule as standard Two Pointer: stop when either pointer exhausts its array, then flush the remainder.

---

## One-Line Recall
**Split by sign → square each half → reverse the negative half → merge two sorted arrays with two pointers.**
