# Dutch National Flag (Sort Colors)

**Pattern:** Two Pointer — Three Pointer variant (Lo/Mid/Hi) · **Difficulty:** Medium · **LeetCode:** Sort Colors

---

## Problem
Given an array containing only three distinct values (`0`, `1`, `2`) in arbitrary order, rearrange it **in-place**, **without using a sort function**, so all `0`s come first, then all `1`s, then all `2`s.

---

## Recognition Signals
- [x] Array? → Yes
- [ ] Sorted? → No, and can't be sorted with a sort function (explicitly disallowed)
- [x] Keyword match? → "rearrange" + "in-place"
- [x] Space constraint? → No extra space allowed

Even without the "sorted" signal, "rearrange" + "in-place" together give ~90% confidence this is Two Pointer.

---

## Core Idea
Three regions of the final array are tracked using **three pointers** (`low`, `mid`, `high`) instead of two — a rare extension of Two Pointer to three coordinated pointers, justified because there are exactly 3 possible values to sort into 3 zones.

- `[start ... low-1]` → confirmed all `0`s
- `[low ... mid-1]` → confirmed all `1`s
- `[mid ... high]` → **unprocessed / unknown** (the only region actually being scanned)
- `[high+1 ... end]` → confirmed all `2`s

`mid` scans through the unknown region; based on what it finds, it swaps into the correct zone and the zone boundaries (`low`/`high`) shift accordingly.

---

## Key Notes
- **Why swap, not just place, this time:** unlike "Remove Duplicates" (where extra values were simply ignored), here every element's original value matters — swapping preserves it rather than discarding it, since it may need to be examined later.
- **Why `mid` doesn't always advance:** when `mid` finds a `2` and swaps it with `high`, the element that comes back from `high` is **unknown** (could be 0, 1, or 2 — that region was never verified) — so `mid` must re-examine that same position rather than assume it's safe to move on. This is the single trickiest part of the algorithm.
- **Why `mid` always advances after finding 0 or 1:** swapping with `low` only ever brings back a `1` (proven, since everything from `low` to `mid-1` is guaranteed `1`), and finding a `1` needs no swap at all — both are "safe" outcomes, so `mid` can confidently move forward.
- **Termination condition:** loop runs `while mid <= high` — stops the moment `mid` crosses `high`, meaning the entire unknown zone has been resolved.
- **This is genuinely a "one-pass" solution** — a key selling point over easier approaches (below) which require 2 full passes over the array.

---

## Approach Comparison

| Approach | Time | Space | Passes | Verdict |
|---|---|---|---|---|
| Brute force (3 separate arrays, then merge back) | O(n) | O(n) | 2 | Works, uses extra space |
| Counting (3 counters, then overwrite) | O(n) | O(1) | 2 | Good — space-optimal but still 2 passes |
| Dutch National Flag (3-pointer) ⭐ | O(n) | O(1) | **1** | Best — single pass, no extra space |

---

## Algorithm Steps
1. `low = 0`, `mid = 0`, `high = n - 1`.
2. While `mid <= high`:
   - **`arr[mid] == 0`:** swap `arr[low]` and `arr[mid]`; `low++`; `mid++`.
   - **`arr[mid] == 1`:** leave in place; `mid++`.
   - **`arr[mid] == 2`:** swap `arr[mid]` and `arr[high]`; `high--`; **do NOT advance `mid`** — re-check the new value at `mid`.
3. Loop ends when `mid > high` — array is fully sorted in-place.

---

## Pseudocode
```
function sortColors(arr):
    n = length(arr)
    low, mid, high = 0, 0, n - 1

    while mid <= high:
        if arr[mid] == 0:
            swap(arr[low], arr[mid])
            low++
            mid++
        elif arr[mid] == 1:
            mid++
        else:  # arr[mid] == 2
            swap(arr[mid], arr[high])
            high--
            # mid stays the same — recheck this position
```

## Dry Run
`arr = [2, 0, 2, 1, 0]` → indices `0 1 2 3 4`, `n = 5`

| low | mid | high | arr[mid] | Action | arr after |
|---|---|---|---|---|---|
| 0 | 0 | 4 | 2 | swap(mid,high); high-- | [0,0,2,1,2] |
| 0 | 0 | 3 | 0 | swap(low,mid); low++; mid++ | [0,0,2,1,2] |
| 1 | 1 | 3 | 0 | swap(low,mid); low++; mid++ | [0,0,2,1,2] |
| 2 | 2 | 3 | 2 | swap(mid,high); high-- | [0,0,1,2,2] |
| 2 | 2 | 2 | 1 | mid++ | [0,0,1,2,2] |
| — | 3 | 2 | — | mid > high → stop | — |

**Result:** `[0, 0, 1, 2, 2]` ✅

---

## Gotchas / Edge Cases
- **Most common bug:** advancing `mid` after a swap-with-`high`. This skips checking the newly-swapped-in value, which could itself be a `0` or `2` needing further action.
- `low` and `mid` both advance together on a `0` — never advance only one.
- On a `1`, no swap is needed at all — just move `mid` forward.
- The "unknown zone" is strictly `mid` to `high` — never assume anything about values there until `mid` actually inspects them.

---

## One-Line Recall
**Three pointers carve the array into 0s | 1s | unknown | 2s; `mid` scans the unknown zone, swapping 0s to the front and 2s to the back — but only advances past 2-swaps after rechecking what came back.**
