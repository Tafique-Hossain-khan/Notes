# Prototype Design Pattern

## The Problem: Expensive Object Creation

Consider an object OB1 created from class A. To create it you write:

```python
a1 = A()
```

Python allocates memory on the heap and the constructor runs. Simple. Now you need a second object, a third, a fourth:

```python
a1 = A()
a2 = A()
a3 = A()
```

Every time you call `A()`, the constructor runs from scratch. This is fine when construction is cheap. But sometimes creating an object is an **expensive operation**. Expensive here means:

- Establishing a database connection
- Running complex calculations
- Loading a complex file from disk
- Making a network request

Any operation that takes significant time. Let's say creating one object takes 5 seconds. If you need 100 such objects, you've just spent 500 seconds — just on object creation.

This is the problem the Prototype Design Pattern solves.

---

## The Solution: Clone Instead of Construct

The Prototype Design Pattern says:

> Create an expensive object **once**. For every additional object you need, don't construct again — just **clone** the existing one.

Cloning is cheap because you're only copying values that already exist. You skip all the expensive operations (DB connections, calculations, file loads) that the constructor would redo.

```python
n1 = NPC()          # expensive — runs full constructor (5 seconds)
n2 = n1.clone()     # cheap — copies values (milliseconds)
n3 = n1.clone()     # cheap — copies values (milliseconds)
```

If you need to tweak the clone slightly, use setters after cloning.

---

## NPC Example

In video games, NPCs (Non-Player Characters) are computer-generated characters — the people walking around on streets in GTA, for example. A game might need hundreds of them when a level loads.

Creating one NPC is expensive: you might need to load textures, query a database for character attributes, run complex initialization logic. But most NPCs look nearly identical — small differences in health, attack power, name.

This is the ideal use case for the Prototype pattern:
- Create **one** NPC with the full expensive constructor
- **Clone** it for every additional NPC needed
- Use setters to apply small differences per clone

---

## Copy Constructor

If you studied C++, you know about the copy constructor. The Prototype Design Pattern uses exactly that concept.

There are three kinds of constructors:

**1. Default constructor** — takes no arguments
```python
def __init__(self):
    pass
```

**2. Parameterised constructor** — takes arguments
```python
def __init__(self, a: int, b: int):
    self.a = a
    self.b = b
```

**3. Copy constructor** — takes a reference to an object of the same class and copies its values
```python
def __init__(self, other: 'A'):
    self.a = other.a
    self.b = other.b
```

The copy constructor is exactly what the Prototype pattern uses. It creates a new object by copying values from an existing object — no expensive operations, just value assignment.

---

## The Cloneable Abstract Class (Marker)

To implement the Prototype pattern, you create an abstract class called `Cloneable` (or `Prototype`). It has exactly one method: `clone()`. Nothing else.

This class acts as a **marker**. It exists only to signal: "any class that inherits from me can be cloned." In Java, there is a formal concept called Marker Interfaces for exactly this — interfaces with no methods that simply mark a class as having a certain capability.

```
┌──────────────────────────────┐
│       Cloneable  (Abstract)  │  ← Marker — just signals "can be cloned"
│──────────────────────────────│
│ + clone() -> Cloneable       │  ← abstract, no implementation here
└──────────────────────────────┘
```

Any class that inherits `Cloneable` must implement `clone()`. The implementation creates a new object using the **copy constructor** (not the expensive parameterised constructor) and returns it.

## UML Diagram

```
┌──────────────────────────────────────────┐
│          Client                          │
│──────────────────────────────────────────│
│ - prototype: Cloneable                   │
│──────────────────────────────────────────│
│ + execute()                              │──► calls prototype.clone()
└──────────────────────────────────────────┘
                    │ holds reference to

│       Cloneable  (Abstract)              │
│──────────────────────────────────────────│

└──────────────────────────────────────────┘
                    │ inherits
                    ▼
┌──────────────────────────────────────────┐
│       ConcretePrototype  (e.g. NPC)      │
│──────────────────────────────────────────│
│ - name: str                              │
│ - health: int                            │
│ - attack: int                            │
│ - defense: int                           │
│──────────────────────────────────────────│
│ + __init__(name, health, attack, defense)│  ← expensive constructor
│ + __init__(other: ConcretePrototype)     │  ← copy constructor (cheap)
│ + clone() -> Cloneable                   │  ← returns new self via copy constructor
│ + describe()                             │
│ + set_name(name)                         │
│ + set_health(health)                     │
│ + set_attack(attack)                     │
│ + set_defense(defense)                   │
└──────────────────────────────────────────┘

clone() implementation inside ConcretePrototype:
    return ConcretePrototype(self)   ← calls copy constructor, NOT expensive constructor
```

**Key flow:**
1. Client holds a reference of type `Cloneable`
2. Client calls `prototype.clone()`
3. `clone()` inside `ConcretePrototype` calls the **copy constructor** with `self`
4. Copy constructor copies all values (name, health, attack, defense) from `self` into new object
5. New object returned — no DB calls, no complex calculations, no file loads

## Python Code — Without Prototype (Bad Design)

```python
import time


class NPC:
    def __init__(self, name: str, health: int, attack: int, defense: int):
        # Simulating expensive constructor operations
        # e.g., database connection, complex calculations, file loading
        print(f"  [Creating NPC '{name}' — expensive operation running...]")
        time.sleep(0.5)   # simulate 0.5s cost per construction

        self.name    = name
        self.health  = health
        self.attack  = attack
        self.defense = defense

    def describe(self):
        print(f"  NPC → name: {self.name} | health: {self.health} "
              f"| attack: {self.attack} | defense: {self.defense}")


# ── Main ───────────────────────────────────────────────────────────────────────

if __name__ == "__main__":
    # Every object calls the expensive constructor
    alien = NPC("Alien", health=30, attack=5, defense=2)
    alien.describe()

    # Want another alien with slightly different defense?
    # Must call the expensive constructor again
    powerful_alien = NPC("Powerful Alien", health=30, attack=5, defense=5)
    powerful_alien.describe()

    # Need 100 aliens? Call the expensive constructor 100 times.
    # Each call costs 0.5 seconds → 50 seconds total for 100 aliens
```

**The problem:** Every `NPC("...", ...)` call re-runs all the expensive operations. For 100 NPCs, you pay the full cost 100 times.

## Python Code — With Prototype Pattern

```python
import time
from abc import ABC, abstractmethod
from copy import copy


# ─── Abstract Cloneable (Marker) ───────────────────────────────────────────────

class Cloneable(ABC):
    """
    Marker abstract class. Signals that any class inheriting this can be cloned.
    Has exactly one method: clone().
    """

    @abstractmethod
    def clone(self) -> 'Cloneable':
        pass


# ─── Concrete Prototype ────────────────────────────────────────────────────────

class NPC(Cloneable):

    def __init__(self, name: str = None, health: int = 0,
                 attack: int = 0, defense: int = 0,
                 _copy_from: 'NPC' = None):
        """
        Two construction paths:
        1. Normal (expensive): pass name, health, attack, defense
        2. Copy (cheap):       pass _copy_from=<existing NPC>
        """
        if _copy_from is not None:
            # ── Copy constructor path — cheap, no expensive operations ──
            self.name    = _copy_from.name
            self.health  = _copy_from.health
            self.attack  = _copy_from.attack
            self.defense = _copy_from.defense
        else:
            # ── Normal constructor path — expensive ──
            print(f"  [Setting up template NPC '{name}' — expensive operation...]")
            time.sleep(0.5)   # simulate DB connection / complex calculation

            self.name    = name
            self.health  = health
            self.attack  = attack
            self.defense = defense

    def clone(self) -> 'Cloneable':
        """
        Returns a clone of self using the copy constructor.
        Does NOT call the expensive normal constructor.
        """
        print(f"  [Cloning NPC '{self.name}' — cheap operation]")
        return NPC(_copy_from=self)

    def describe(self):
        print(f"  NPC → name: {self.name} | health: {self.health} "
              f"| attack: {self.attack} | defense: {self.defense}")

    # ── Setters for post-clone tweaks ──────────────────────────────────────────
    def set_name(self, name: str):     self.name    = name
    def set_health(self, health: int): self.health  = health
    def set_attack(self, attack: int): self.attack  = attack
    def set_defense(self, defense: int): self.defense = defense


# ── Main ───────────────────────────────────────────────────────────────────────

if __name__ == "__main__":

    # Create the first NPC the expensive way — pay the cost only once
    alien = NPC(name="Alien", health=30, attack=5, defense=2)
    alien.describe()

    print()

    # Clone alien — cheap, no expensive operations run
    alien_copy = alien.clone()
    alien_copy.describe()   # identical to alien

    print()

    # Clone alien again and tweak with setters — still cheap
    alien_copy2 = alien.clone()
    alien_copy2.set_name("Powerful Alien")
    alien_copy2.set_health(50)
    alien_copy2.describe()
```

**Expected output:**
```
  [Setting up template NPC 'Alien' — expensive operation...]
  NPC → name: Alien | health: 30 | attack: 5 | defense: 2

  [Cloning NPC 'Alien' — cheap operation]
  NPC → name: Alien | health: 30 | attack: 5 | defense: 2

  [Cloning NPC 'Alien' — cheap operation]
  NPC → name: Powerful Alien | health: 50 | attack: 5 | defense: 2
```

The expensive setup runs **once**. Every subsequent NPC is created in milliseconds.

## Shallow Copy vs Deep Copy

When implementing the copy constructor, you must choose between shallow copy and deep copy. This distinction matters when your class has fields that are **non-primitive** (objects, lists, other class instances).

### Primitive fields — no problem

For primitive types (int, float, str, bool), copying just copies the value:

```python
# Original object has: x = 20 at memory address 1001
# Copy object has:     x = 20 at memory address 1002
# Changing copy's x doesn't affect original's x
```

Primitives always behave like deep copy automatically.

### Non-primitive fields — the shallow copy problem

Suppose `NPC` had a field that is itself an object:

```python
class NPC:
    def __init__(self):
        self.weapon = Weapon()   # non-primitive field
```

If your copy constructor does this:

```python
def __init__(self, _copy_from: 'NPC' = None):
    if _copy_from:
        self.weapon = _copy_from.weapon   # SHALLOW COPY
```

Both the original and the clone now point to the **same** `Weapon` object in memory. Changing the weapon in the clone changes it in the original too. This is a **shallow copy**.

```
Original NPC   ──► weapon object (heap address 5001)
Cloned NPC     ──► weapon object (heap address 5001)  ← same object!
```

### Deep copy — the correct approach

For non-primitive fields, create a new object:

```python
def __init__(self, _copy_from: 'NPC' = None):
    if _copy_from:
        self.weapon = Weapon(_copy_from=_copy_from.weapon)   # DEEP COPY
```

Now the clone has its own independent `Weapon` object:

```
Original NPC   ──► weapon object (heap address 5001)
Cloned NPC     ──► weapon object (heap address 5002)  ← independent copy!
```

Changing the clone's weapon does not affect the original.

### Python code illustrating both

```python
class Weapon:
    def __init__(self, damage: int = 10, _copy_from: 'Weapon' = None):
        if _copy_from:
            self.damage = _copy_from.damage
        else:
            self.damage = damage

    def set_damage(self, d: int): self.damage = d


class NPCShallow:
    """Demonstrates shallow copy problem with non-primitive fields."""

    def __init__(self, name: str = None, _copy_from: 'NPCShallow' = None):
        if _copy_from:
            self.name   = _copy_from.name
            self.weapon = _copy_from.weapon   # shallow — same object reference
        else:
            self.name   = name
            self.weapon = Weapon(damage=10)

    def describe(self):
        print(f"  {self.name} | weapon damage: {self.weapon.damage}")


class NPCDeep:
    """Demonstrates correct deep copy with non-primitive fields."""

    def __init__(self, name: str = None, _copy_from: 'NPCDeep' = None):
        if _copy_from:
            self.name   = _copy_from.name
            self.weapon = Weapon(_copy_from=_copy_from.weapon)  # deep — new object
        else:
            self.name   = name
            self.weapon = Weapon(damage=10)

    def describe(self):
        print(f"  {self.name} | weapon damage: {self.weapon.damage}")


if __name__ == "__main__":

    print("=== Shallow Copy Problem ===")
    original = NPCShallow(name="Alien")
    clone    = NPCShallow(_copy_from=original)

    clone.weapon.set_damage(99)          # change only the clone's weapon
    original.describe()                  # original also shows 99 — problem!
    clone.describe()

    print()

    print("=== Deep Copy Solution ===")
    original2 = NPCDeep(name="Alien")
    clone2    = NPCDeep(_copy_from=original2)

    clone2.weapon.set_damage(99)         # change only the clone's weapon
    original2.describe()                 # original still shows 10 — correct!
    clone2.describe()
```

**Expected output:**
```
=== Shallow Copy Problem ===
  Alien | weapon damage: 99    ← original was changed too!
  Alien | weapon damage: 99

=== Deep Copy Solution ===
  Alien | weapon damage: 10    ← original unchanged
  Alien | weapon damage: 99
```

**Rule:** For primitive fields → copying the value is sufficient (behaves like deep copy). For non-primitive fields → you must create a new object using `new` / constructor call, otherwise both original and clone share the same heap object.

## Standard UML (Generic Pattern)

```
┌──────────────────────────────┐
│           Client             │
│──────────────────────────────│
│ - p: Prototype               │
│──────────────────────────────│
│ + execute()                  │──► p.clone()
└──────────────────────────────┘
              │ references
              ▼
┌──────────────────────────────┐
│     Prototype  (Abstract)    │
│──────────────────────────────│
│ + clone() -> Prototype       │  ← abstract
└──────────────────────────────┘
              │ inherits
              ▼
┌──────────────────────────────┐
│    ConcretePrototype         │
│──────────────────────────────│
│ + __init__(other=None)       │  ← copy constructor path
│ + clone() -> Prototype       │  ← return ConcretePrototype(_copy_from=self)
└──────────────────────────────┘
```

`clone()` inside `ConcretePrototype` always does:
```python
return ConcretePrototype(_copy_from=self)
```

This calls the copy constructor, not the expensive normal constructor. The client gets back a `Prototype` reference pointing to a new fully-copied `ConcretePrototype` object.

---

## Standard Definition

> **Prototype Design Pattern** lets you create new objects by copying (cloning) an existing instance.

Instead of calling `new SomeClass(...)` which re-runs all the expensive setup, you call `.clone()` on an existing object. The clone copies values from the existing object, skipping all expensive operations.

When to use it: any scenario where objects are expensive to create, and many needed objects are similar to each other with only small differences.

---

## Real World Use Cases

- **NPCs in games** — the primary example. Hundreds of similar characters needed at level load time. Create one template, clone the rest.
- **Any object requiring DB connection on construction** — pay the connection cost once, clone for additional instances.
- **Any object requiring complex calculations during initialization** — calculate once, clone for copies.
- **Any object loading large files or making network requests during construction** — load once, clone for copies.

The pattern is most valuable when: (a) construction is expensive, and (b) the many objects you need are mostly similar with only small tweaks per object.

If every object needs completely different values, cloning doesn't help — you'd clone and then set every field anyway, which gains nothing.
