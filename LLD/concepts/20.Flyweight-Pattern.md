# Flyweight Design Pattern

## The Problem: RAM is Limited

Every object you create lives in RAM. In most programs, creating a few thousand objects is fine. But imagine a scenario where you are creating **millions of objects** — and each one occupies memory. If your RAM is limited, your application crashes.

The Flyweight pattern exists for exactly one reason: **to save RAM by reusing objects instead of creating new ones every time.**

---

## The Game Example

Imagine you are building a space game. Your spaceship shoots lasers and asteroids come flying at you from the screen. On harder levels, hundreds of thousands of asteroids appear at once. Each asteroid is an object. Create a million asteroids and your RAM fills up and the game crashes.

Now, what does an asteroid look like as a class?

```
Asteroid:
  - length     (int)
  - width      (int)
  - weight     (int)
  - colour     (str)
  - texture    (str)
  - position_x (int)   ← where it is on screen right now
  - position_y (int)   ← where it is on screen right now
  - velocity_x (int)   ← how fast it is moving
  - velocity_y (int)   ← how fast it is moving
```

One asteroid might take ~196 bytes. A million asteroids → ~187 MB. For a game, that is enormous.

But look carefully at those properties. Some of them repeat across many asteroids, and some of them are always unique.

---

## Intrinsic vs Extrinsic Properties

The Flyweight pattern says: split every object into two parts.

**Intrinsic properties** — properties that are **shared** across many objects. They can be reused. In the asteroid example:

- `length`, `width`, `weight`, `colour`, `texture`

Why shared? Because there are only a limited number of possible values. Length can only be 10, 20, or 30. Colour can only be Red, Green, or Blue. Texture can only be Hard, Soft, or Semi-hard. There are only **3 × 3 × 3 × 3 × 3 = 243** combinations at most — and in practice far fewer.

**Extrinsic properties** — properties that are **unique** to each object. They cannot be reused. In the asteroid example:

- `position_x`, `position_y`, `velocity_x`, `velocity_y`

Why unique? Because every asteroid appears at a different position on screen and moves at a different speed. These values vary enormously and cannot be shared.

---

## The Solution

Remove all extrinsic properties from the main object. What remains — the object containing only intrinsic properties — is the **Flyweight object**.

Create a separate **Context class** to hold the extrinsic properties. The Context class holds a reference to a Flyweight object.

Instead of creating 1,000,000 unique asteroid objects, you:
- Create at most as many Flyweight objects as there are **unique combinations** of intrinsic properties (e.g., 3 in our example)
- Create 1,000,000 Context objects (one per asteroid), each holding only the 4 extrinsic values plus a reference to one of the 3 shared Flyweight objects

The math:
- **Without Flyweight:** 1,000,000 × full asteroid = ~187 MB
- **With Flyweight:** 1,000,000 × small context + 3 × flyweight = ~22 MB

---

## How the Flyweight Factory Works

You need something to manage the Flyweight objects — to ensure you never create two identical ones. That is the **Flyweight Factory**.

The Factory uses a **map (dictionary)** internally:
- Key: a string built by concatenating the intrinsic property values, e.g. `"25_25_250_Red_Hard_Iron"`
- Value: the Flyweight object for that combination

When someone asks for a Flyweight:
1. Build the key from the given intrinsic values.
2. Check if this key already exists in the map.
3. If yes → return the existing object (reuse).
4. If no → create a new Flyweight, store it in the map, return it.

This way, no matter how many times you ask for a "Red, Hard, Iron, length=25" asteroid, you get back the **same object**.

## Python Implementation

### Without Flyweight (for comparison)

```python
import sys


class AsteroidWithoutFlyweight:
    """
    Single class holding ALL properties — both intrinsic and extrinsic.
    Every asteroid is a completely new object. Memory usage explodes.
    """

    def __init__(self, length: int, width: int, weight: int,
                 colour: str, texture: str, material: str,
                 position_x: int, position_y: int,
                 velocity_x: int, velocity_y: int):
        self.length = length
        self.width = width
        self.weight = weight
        self.colour = colour
        self.texture = texture
        self.material = material
        self.position_x = position_x
        self.position_y = position_y
        self.velocity_x = velocity_x
        self.velocity_y = velocity_y

    def render(self):
        print(
            f"Rendering [{self.colour}, {self.texture}, {self.material}] asteroid "
            f"at ({self.position_x}, {self.position_y}) "
            f"size=({self.length}x{self.width}) velocity=({self.velocity_x},{self.velocity_y})"
        )

    def get_memory_usage(self) -> int:
        return sys.getsizeof(self)


class SpaceGameWithoutFlyweight:
    def __init__(self):
        self._asteroids: list[AsteroidWithoutFlyweight] = []

    def spawn_asteroids(self, count: int):
        print(f"Spawning {count:,} asteroids (without Flyweight)...")

        colours   = ["Red", "Blue", "Grey"]
        textures  = ["Rocky", "Metallic", "Icy"]
        materials = ["Iron", "Stone", "Ice"]
        sizes     = [25, 35, 45]

        for i in range(count):
            t = i % 3
            self._asteroids.append(AsteroidWithoutFlyweight(
                length=sizes[t], width=sizes[t], weight=sizes[t] * 10,
                colour=colours[t], texture=textures[t], material=materials[t],
                position_x=100 + i * 50,
                position_y=200 + i * 30,
                velocity_x=1,
                velocity_y=2
            ))
        print(f"Created {len(self._asteroids):,} asteroid objects")

    def render_all(self, max_render: int = 5):
        for i in range(min(max_render, len(self._asteroids))):
            self._asteroids[i].render()

    def calculate_memory_usage(self) -> dict:
        if not self._asteroids:
            return {}
        per_object = self._asteroids[0].get_memory_usage()
        total_bytes = per_object * len(self._asteroids)
        return {
            "total_objects": len(self._asteroids),
            "bytes_per_object": per_object,
            "total_bytes": total_bytes,
            "total_mb": total_bytes / (1024 * 1024),
        }
```

### With Flyweight

```python
import sys


# -----------------------------------------------------------------------
# FLYWEIGHT OBJECT — holds only INTRINSIC (shared) properties
# -----------------------------------------------------------------------

class AsteroidFlyweight:
    """
    Holds only the shared, reusable intrinsic properties.
    Extrinsic properties (position, velocity) are NOT stored here.
    They are passed in at render time from the Context.

    This object should be treated as immutable — changing it changes
    ALL contexts that reference it.
    """

    def __init__(self, length: int, width: int, weight: int,
                 colour: str, texture: str, material: str):
        self.length   = length
        self.width    = width
        self.weight   = weight
        self.colour   = colour
        self.texture  = texture
        self.material = material

    def render(self, position_x: int, position_y: int,
               velocity_x: int, velocity_y: int):
        """
        Extrinsic properties are passed in as parameters — not stored.
        The Context calls this method and provides its own values.
        """
        print(
            f"Rendering [{self.colour}, {self.texture}, {self.material}] asteroid "
            f"at ({position_x}, {position_y}) "
            f"size=({self.length}x{self.width}) velocity=({velocity_x},{velocity_y})"
        )

    def get_memory_usage(self) -> int:
        return sys.getsizeof(self)


# -----------------------------------------------------------------------
# FLYWEIGHT FACTORY — ensures no duplicate Flyweight objects are created
# -----------------------------------------------------------------------

class AsteroidFactory:
    """
    Manages the pool of shared Flyweight objects.
    Uses a dictionary keyed by the intrinsic property combination.

    If a Flyweight for that combination already exists → return it (reuse).
    If not → create it, store it, return it.
    """

    _pool: dict[str, AsteroidFlyweight] = {}

    @classmethod
    def get_asteroid(cls, length: int, width: int, weight: int,
                     colour: str, texture: str, material: str) -> AsteroidFlyweight:
        # Build a unique key from all intrinsic properties
        key = f"{length}_{width}_{weight}_{colour}_{texture}_{material}"

        if key not in cls._pool:
            # First time this combination is requested — create and cache it
            cls._pool[key] = AsteroidFlyweight(
                length=length, width=width, weight=weight,
                colour=colour, texture=texture, material=material
            )
        # Return the shared object (existing or newly created)
        return cls._pool[key]

    @classmethod
    def get_flyweight_count(cls) -> int:
        """Returns how many unique Flyweight objects were actually created."""
        return len(cls._pool)

    @classmethod
    def get_total_flyweight_memory(cls) -> int:
        if not cls._pool:
            return 0
        per_flyweight = next(iter(cls._pool.values())).get_memory_usage()
        return per_flyweight * len(cls._pool)

    @classmethod
    def clear(cls):
        cls._pool.clear()


# -----------------------------------------------------------------------
# CONTEXT CLASS — holds only EXTRINSIC (unique) properties
# -----------------------------------------------------------------------

class AsteroidContext:
    """
    Holds the unique, per-asteroid extrinsic properties.
    Also holds a reference to a shared AsteroidFlyweight.

    This is what the client code interacts with.
    The client does not need to know that AsteroidFlyweight exists separately.
    """

    def __init__(self, flyweight: AsteroidFlyweight,
                 position_x: int, position_y: int,
                 velocity_x: int, velocity_y: int):
        self._flyweight  = flyweight    # reference to shared object
        self.position_x  = position_x  # unique per asteroid
        self.position_y  = position_y  # unique per asteroid
        self.velocity_x  = velocity_x  # unique per asteroid
        self.velocity_y  = velocity_y  # unique per asteroid

    def render(self):
        """
        Client calls render() on the Context.
        Context passes its own extrinsic values into the Flyweight's render().
        """
        self._flyweight.render(
            self.position_x, self.position_y,
            self.velocity_x, self.velocity_y
        )

    def get_memory_usage(self) -> int:
        # Context's own fields + size of the reference to flyweight
        return sys.getsizeof(self)


# -----------------------------------------------------------------------
# SPACE GAME — the client
# -----------------------------------------------------------------------

class SpaceGameWithFlyweight:
    def __init__(self):
        self._asteroids: list[AsteroidContext] = []

    def spawn_asteroids(self, count: int):
        print(f"\nSpawning {count:,} asteroids (WITH Flyweight)...")

        colours   = ["Red", "Blue", "Grey"]
        textures  = ["Rocky", "Metallic", "Icy"]
        materials = ["Iron", "Stone", "Ice"]
        sizes     = [25, 35, 45]

        for i in range(count):
            t = i % 3

            # Get (or reuse) the shared Flyweight for this combination
            flyweight = AsteroidFactory.get_asteroid(
                length=sizes[t], width=sizes[t], weight=sizes[t] * 10,
                colour=colours[t], texture=textures[t], material=materials[t]
            )

            # Create a new Context with unique extrinsic properties
            # Context holds the Flyweight reference — not a copy
            self._asteroids.append(AsteroidContext(
                flyweight=flyweight,
                position_x=100 + i * 50,
                position_y=200 + i * 30,
                velocity_x=1,
                velocity_y=2
            ))

        print(f"Created {len(self._asteroids):,} asteroid contexts")
        print(f"Total unique Flyweight objects created: "
              f"{AsteroidFactory.get_flyweight_count()}")

    def render_all(self, max_render: int = 5):
        for i in range(min(max_render, len(self._asteroids))):
            self._asteroids[i].render()

    def calculate_memory_usage(self) -> dict:
        if not self._asteroids:
            return {}

        context_bytes   = self._asteroids[0].get_memory_usage() * len(self._asteroids)
        flyweight_bytes = AsteroidFactory.get_total_flyweight_memory()
        total_bytes     = context_bytes + flyweight_bytes

        return {
            "total_contexts":      len(self._asteroids),
            "unique_flyweights":   AsteroidFactory.get_flyweight_count(),
            "context_bytes":       context_bytes,
            "flyweight_bytes":     flyweight_bytes,
            "total_bytes":         total_bytes,
            "total_mb":            total_bytes / (1024 * 1024),
        }


# -----------------------------------------------------------------------
# COMPARISON: run both and print memory usage
# -----------------------------------------------------------------------

if __name__ == "__main__":
    ASTEROID_COUNT = 1_000_000

    # --- WITHOUT FLYWEIGHT ---
    print("=" * 60)
    print("TESTING WITHOUT FLYWEIGHT")
    print("=" * 60)

    game_plain = SpaceGameWithoutFlyweight()
    game_plain.spawn_asteroids(ASTEROID_COUNT)

    print("\nRendering first 5 asteroids:")
    game_plain.render_all(max_render=5)

    stats_plain = game_plain.calculate_memory_usage()
    print(f"\nMemory per asteroid : {stats_plain['bytes_per_object']} bytes")
    print(f"Total objects       : {stats_plain['total_objects']:,}")
    print(f"Total memory        : {stats_plain['total_bytes']:,} bytes")
    print(f"Total memory        : {stats_plain['total_mb']:.2f} MB")

    # --- WITH FLYWEIGHT ---
    print("\n" + "=" * 60)
    print("TESTING WITH FLYWEIGHT PATTERN")
    print("=" * 60)

    AsteroidFactory.clear()
    game_flyweight = SpaceGameWithFlyweight()
    game_flyweight.spawn_asteroids(ASTEROID_COUNT)

    print("\nRendering first 5 asteroids:")
    game_flyweight.render_all(max_render=5)

    stats_fw = game_flyweight.calculate_memory_usage()
    print(f"\nTotal Context objects      : {stats_fw['total_contexts']:,}")
    print(f"Unique Flyweight objects   : {stats_fw['unique_flyweights']}")
    print(f"Context memory             : {stats_fw['context_bytes']:,} bytes")
    print(f"Flyweight memory           : {stats_fw['flyweight_bytes']:,} bytes")
    print(f"Total memory               : {stats_fw['total_bytes']:,} bytes")
    print(f"Total memory               : {stats_fw['total_mb']:.2f} MB")

    # --- SUMMARY ---
    print("\n" + "=" * 60)
    print("MEMORY SAVED")
    print("=" * 60)
    saved = stats_plain['total_mb'] - stats_fw['total_mb']
    print(f"Without Flyweight : {stats_plain['total_mb']:.2f} MB")
    print(f"With Flyweight    : {stats_fw['total_mb']:.2f} MB")
    print(f"RAM saved         : ~{saved:.2f} MB")
```

## What Just Happened

Without Flyweight: 1,000,000 full asteroid objects. All 10 properties stored per object.

With Flyweight: 1,000,000 small Context objects (only 4 extrinsic values + a reference) + **3 Flyweight objects** (because there were only 3 unique intrinsic combinations in the game logic).

The 3 Flyweight objects are shared. When asteroid 1 and asteroid 3,001 both have the same colour/texture/material/size, they **point to the same Flyweight object in memory**.

---

## The Immutability Warning

The Flyweight object must be treated as **immutable** (or you must be very careful if you allow mutation).

Why? Because one Flyweight object is shared by potentially hundreds of thousands of Context objects. If you change `flyweight.colour = "Purple"`, every asteroid referencing that Flyweight changes colour at once. The client never asked for that. In Python, enforce this with `@property` with no setter, or use `__slots__` and document it clearly.

---

## The Standard Definition

> Flyweight uses sharing to support a large number of fine-grained objects efficiently.

**Intrinsic state** — shared among objects. Stored in the Flyweight. The Flyweight holds this.

**Extrinsic state** — unique per object. Supplied by the client externally. The Context holds this and passes it to the Flyweight when needed (e.g., at render time).

---

## Real-World Use Cases

**Open-world games (GTA, etc.):** In large open-world games, many NPCs look identical — same model, same walking animation, same clothing. Those shared visual properties are Flyweights. Each NPC has its own position and state (extrinsic) but shares the visual representation (intrinsic). This is how games render hundreds of similar NPCs without running out of RAM.

**Text editors:** In a text editor, every character typed is represented by an object. But there are only 26 lowercase letters, 26 uppercase, 10 digits, and a few punctuation marks. The visual representation of each 'a' is always the same — that is intrinsic. What varies is the position in the document, and possibly the font size applied to that specific 'a' — those are extrinsic. The same Flyweight for 'a' is reused every time the letter 'a' appears, regardless of how many times it appears in the document.
