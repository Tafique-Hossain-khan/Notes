# 3Sum Closest

**Pattern:** Two Pointer (3Sum variant) · **Difficulty:** Medium · **LeetCode:** 3Sum Closest

---

## Problem
Given an array and a `target`, find three numbers whose sum is **closest** to `target` (not necessarily equal). Return that sum. Assume exactly one solution exists (no duplicate-handling needed).

---

## Recognition Signals
- [x] Array? → Yes
- [x] Sorted / sortable? → Sort first, same as 3Sum
- [x] Keyword match? → "three numbers" → 3Sum-family, Two Pointer
- [x] Space constraint? → Not relevant; this is a 3Sum logic variant

---

## Core Idea
**Identical skeleton to 3Sum** (fix `i`, run Two Pointer on the rest) — but instead of checking `sum == 0` and stopping, track the sum with the **smallest absolute distance** from `target` seen so far, and keep scanning through the entire array.

---

## Key Notes
- **Why `sum == target` is still checked first:** a distance of 0 is mathematically the best possible outcome — `abs(sum - target)` can never go below 0 — so an exact match is guaranteed to be the best answer if it occurs.
- **Why `bestDiff` starts at infinity:** guarantees the very first computed difference will always be "better," so it initializes correctly regardless of the actual data.
- **No duplicate-skip logic here:** unlike 3Sum, the problem guarantees exactly one solution, so there's no need to worry about repeated triplets — this simplifies the code versus 3Sum.
- **Relationship to 3Sum:** same core loop (`i`, `left`, `right`, same three-way branch on sum vs target) — only the "on match" action changes from "collect and dedupe" to "compare and possibly update the best-so-far."

---

## Approach Comparison

| Approach | Time | Space | Verdict |
|---|---|---|---|
| Brute force (3 nested loops, track best) | O(n³) | O(1) | Too slow |
| Two Pointer (3Sum skeleton) ⭐ | O(n²) | O(1) | Optimal |

---

## Algorithm Steps
1. Sort the array.
2. `bestDiff = infinity`, `bestSum = undefined`.
3. For `i = 0` to `n - 3`:
   - `left = i + 1`, `right = n - 1`.
   - While `left < right`:
     - `sum = arr[i] + arr[left] + arr[right]`
     - `diff = abs(sum - target)`
     - If `diff < bestDiff`: `bestDiff = diff`, `bestSum = sum`.
     - `sum == target` → best possible; move both pointers to continue scanning.
     - `sum < target` → `left++`
     - `sum > target` → `right--`
4. Return `bestSum`.

---

## Pseudocode
```
function threeSumClosest(arr, target):
    sort(arr)
    n = length(arr)
    bestDiff = infinity
    bestSum = 0

    for i = 0 to n - 3:
        left, right = i + 1, n - 1
        while left < right:
            sum = arr[i] + arr[left] + arr[right]
            diff = abs(sum - target)

            if diff < bestDiff:
                bestDiff = diff
                bestSum = sum

            if sum == target:
                left++
                right--
            elif sum < target:
                left++
            else:
                right--

    return bestSum
```

## Dry Run
`arr = [-1, 2, 1, -4]` → sorted: `[-4, -1, 1, 2]`, `target = 1`

| i | left,right | sum | diff | bestSum updated? |
|---|---|---|---|---|
| -4 | left=-1,right=2 | -3 | 4 | yes → bestSum=-3, bestDiff=4 |
| -4 | left=1,right=2 | -1 | 2 | yes → bestSum=-1, bestDiff=2 |
| -1 | left=1,right=2 | 2 | 1 | yes → bestSum=2, bestDiff=1 |

**Result:** `2` (closest to target `1`)

---

## Gotchas / Edge Cases
- Don't `return` immediately on `sum == target` unless certain — technically 0 diff is unbeatable, but since input guarantees one solution, letting the loop naturally continue and exit is safe and simpler.
- No duplicate-checking needed here — a key structural difference from 3Sum. Don't copy the dedup logic over by habit.
- `abs()` is essential — without it, a sum of `target - 5` and `target + 3` would be compared incorrectly (raw difference can be negative).
