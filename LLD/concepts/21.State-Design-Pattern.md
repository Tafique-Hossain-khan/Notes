# State Design Pattern

## What is the State Design Pattern?

Consider an object that can exist in a limited number of states at any given time. Let's call them State A, State B, and State C. This object moves back and forth between these states. When you perform an operation `m1` on the object while it's in State A, it transitions to State B. Perform `m2` on State B, and it moves to State C. Perform `m3` on State C, and it goes back to State A.

This is the core idea. You have:
- A **finite, limited number of states**
- A **finite, limited number of operations**
- Each operation on a particular state either transitions to a new state or keeps the object in the same state

When an object behaves this way, the **State Design Pattern** is the right tool.

---

## State Machine Diagram (SMD)

Before writing any code, you need to understand how to draw a State Machine Diagram. If you studied Theory of Computation (TOC) in college, you've already drawn these.

The idea is simple. You have an object with some states and some methods. Draw circles for each state. Draw arrows between states labeled with the method that causes that transition.

**Example with 4 states and 4 methods:**

```
States:  A, B, C, D
Methods: m1, m2, m3, m4

A --m1--> B
B --m2--> C
C --m3--> D
D --m4--> A
```

What if you're in State A and call `m2` instead of `m1`? You might go to State C directly, or stay in State A, or go somewhere else entirely. There are many permutations. Sometimes an object stays in the same state because the operation isn't valid in that state — represented as a self-loop arrow back to the same state.

## The Vending Machine Example

We'll build a simple vending machine. It only dispenses water bottles. Each bottle costs ₹20. You can only insert coins (no digital payments). This keeps things focused on the pattern itself.

### States

| State | Meaning |
|---|---|
| **No Coin State** | Machine is idle, no coin inserted |
| **Has Coin State** | A coin has been inserted |
| **Dispense State** | An item is being dispensed |
| **Sold Out State** | All items are finished |

### Operations

| Operation | Meaning |
|---|---|
| `insert_coin` | User inserts a coin |
| `select_item` | User selects an item from keypad |
| `dispense` | Machine physically dispenses the item |
| `return_coin` | Machine returns inserted coins to user |
| `refill` | Admin refills the machine with items |

---

## Complete State Machine Diagram

```
[No Coin] --insert_coin--> [Has Coin]
[Has Coin] --select_item--> [Dispense]
[Has Coin] --return_coin--> [No Coin]
[Dispense] --dispense (items remain)--> [No Coin]
[Dispense] --dispense (items gone)--> [Sold Out]
[Sold Out] --refill--> [No Coin]
```

All other operation+state combinations loop back to the same state (nothing happens, possibly an error message).

### Full Transition Table

| | `insert_coin` | `select_item` | `dispense` | `return_coin` | `refill` |
|---|---|---|---|---|---|
| **No Coin** | → Has Coin | stay | stay | stay | stay |
| **Has Coin** | stay | → Dispense | stay | → No Coin | stay |
| **Dispense** | stay | stay | → No Coin or Sold Out | stay | stay |
| **Sold Out** | stay | stay | stay | stay | → No Coin |

**Key insight:** "Stay" doesn't always mean do nothing. It means the state doesn't change. The machine may still print an error message. For example:
- In No Coin State, calling `select_item` → machine prints "Please insert coin first"
- In Has Coin State, calling `dispense` → machine prints "Please select an item first"
- In Sold Out State, calling `insert_coin` → machine prints "Machine is sold out"

Also note: In Has Coin State, calling `insert_coin` again is valid (machine accepts more coins) — it just stays in Has Coin State with an updated coin total.

## UML Diagram

The pattern has two sides:

**1. The State Hierarchy** — an abstract class with all possible operations, and one concrete class per state.

**2. The Context Class** — the vending machine itself, which holds a reference to the current state and delegates every method call to it.

```
┌─────────────────────────────────────┐
│         VendingMachineState         │  ← Abstract Class
│─────────────────────────────────────│
│ + insert_coin(machine) : VMState    │
│ + select_item(machine) : VMState    │
│ + dispense(machine)    : VMState    │
│ + return_coin(machine) : VMState    │
│ + refill(machine, qty) : VMState    │
└──────────────┬──────────────────────┘
               │ inherits
    ┌──────────┼──────────┬─────────────┐
    ▼          ▼          ▼             ▼
┌────────┐ ┌────────┐ ┌──────────┐ ┌──────────┐
│NoCoin  │ │HasCoin │ │Dispense  │ │ SoldOut  │
│State   │ │State   │ │State     │ │ State    │
└────┬───┘ └───┬────┘ └────┬─────┘ └────┬─────┘
     │         │           │             │
     └─────────┴───────────┴─────────────┘
          concrete states reference each other


┌─────────────────────────────────┐
│         VendingMachine          │  ← Context Class
│─────────────────────────────────│
│ - current_state: VMState        │
│ - no_coin_state: NoCoinState    │
│ - has_coin_state: HasCoinState  │
│ - dispense_state: DispenseState │
│ - sold_out_state: SoldOutState  │
│ - item_count: int               │
│ - item_price: int               │
│ - inserted_coins: int           │
│─────────────────────────────────│
│ + insert_coin(coin)             │  ← delegates to current_state
│ + select_item()                 │  ← delegates to current_state
│ + dispense()                    │  ← delegates to current_state
│ + return_coin()                 │  ← delegates to current_state
│ + refill(qty)                   │  ← delegates to current_state
└─────────────────────────────────┘
```

**How delegation works:**

When a client calls `machine.insert_coin(10)`, the vending machine does exactly one thing internally:

```python
self.current_state = self.current_state.insert_coin(self, 10)
```

It passes itself (`self`) as a reference so the state can read/modify machine data, and it updates `current_state` with whatever state is returned. The vending machine is a "dumb object" — it knows nothing about business logic. All logic lives inside the state classes.

**Why pre-create all state objects in the constructor?**

Instead of creating a new object every time a state transition happens, the machine pre-creates one object for each concrete state and stores references. When transitioning, states return references to these pre-created objects. This avoids unnecessary object creation.

## Python Implementation

```python
from __future__ import annotations
from abc import ABC, abstractmethod


# ─── Abstract State ────────────────────────────────────────────────────────────

class VendingMachineState(ABC):

    @abstractmethod
    def insert_coin(self, machine: VendingMachine, coin: int) -> VendingMachineState:
        pass

    @abstractmethod
    def select_item(self, machine: VendingMachine) -> VendingMachineState:
        pass

    @abstractmethod
    def dispense(self, machine: VendingMachine) -> VendingMachineState:
        pass

    @abstractmethod
    def return_coin(self, machine: VendingMachine) -> VendingMachineState:
        pass

    @abstractmethod
    def refill(self, machine: VendingMachine, quantity: int) -> VendingMachineState:
        pass

    @abstractmethod
    def get_state_name(self) -> str:
        pass


# ─── Context Class ─────────────────────────────────────────────────────────────

class VendingMachine:

    def __init__(self, item_count: int, item_price: int):
        self.item_count = item_count
        self.item_price = item_price
        self.inserted_coins = 0

        # Pre-create one object per concrete state
        self._no_coin_state    = NoCoinState()
        self._has_coin_state   = HasCoinState()
        self._dispense_state   = DispenseState()
        self._sold_out_state   = SoldOutState()

        # Set initial state
        if self.item_count > 0:
            self.current_state = self._no_coin_state
        else:
            self.current_state = self._sold_out_state

    # ── Getters for states (used by concrete states to return references) ──
    def get_no_coin_state(self)  -> VendingMachineState: return self._no_coin_state
    def get_has_coin_state(self) -> VendingMachineState: return self._has_coin_state
    def get_dispense_state(self) -> VendingMachineState: return self._dispense_state
    def get_sold_out_state(self) -> VendingMachineState: return self._sold_out_state

    # ── Item and coin helpers ──
    def get_item_count(self)     -> int: return self.item_count
    def get_item_price(self)     -> int: return self.item_price
    def get_inserted_coins(self) -> int: return self.inserted_coins

    def set_inserted_coins(self, amount: int):    self.inserted_coins = amount
    def add_coins(self, coin: int):               self.inserted_coins += coin
    def decrement_item_count(self):               self.item_count -= 1
    def increment_item_count(self, qty: int):     self.item_count += qty

    # ── Delegate methods (the vending machine itself does nothing but delegate) ──
    def insert_coin(self, coin: int):
        self.current_state = self.current_state.insert_coin(self, coin)

    def select_item(self):
        self.current_state = self.current_state.select_item(self)

    def dispense(self):
        self.current_state = self.current_state.dispense(self)

    def return_coin(self):
        self.current_state = self.current_state.return_coin(self)

    def refill(self, quantity: int):
        self.current_state = self.current_state.refill(self, quantity)

    def print_status(self):
        print(f"\n[STATUS] Items remaining: {self.item_count} | "
              f"Inserted coins: ₹{self.inserted_coins} | "
              f"Current state: {self.current_state.get_state_name()}")


# ─── Concrete State: No Coin ────────────────────────────────────────────────────

class NoCoinState(VendingMachineState):

    def insert_coin(self, machine: VendingMachine, coin: int) -> VendingMachineState:
        machine.add_coins(coin)
        print(f"Coin inserted. Current balance: ₹{machine.get_inserted_coins()}")
        return machine.get_has_coin_state()

    def select_item(self, machine: VendingMachine) -> VendingMachineState:
        print("Please insert a coin first.")
        return machine.get_no_coin_state()

    def dispense(self, machine: VendingMachine) -> VendingMachineState:
        print("Please insert a coin and select an item first.")
        return machine.get_no_coin_state()

    def return_coin(self, machine: VendingMachine) -> VendingMachineState:
        print("No coin to return.")
        return machine.get_no_coin_state()

    def refill(self, machine: VendingMachine, quantity: int) -> VendingMachineState:
        print(f"Refilling machine with {quantity} items.")
        machine.increment_item_count(quantity)
        return machine.get_no_coin_state()

    def get_state_name(self) -> str:
        return "No Coin State"


# ─── Concrete State: Has Coin ───────────────────────────────────────────────────

class HasCoinState(VendingMachineState):

    def insert_coin(self, machine: VendingMachine, coin: int) -> VendingMachineState:
        machine.add_coins(coin)
        print(f"Additional coin inserted. Current balance: ₹{machine.get_inserted_coins()}")
        return machine.get_has_coin_state()   # stay in same state

    def select_item(self, machine: VendingMachine) -> VendingMachineState:
        if machine.get_inserted_coins() >= machine.get_item_price():
            change = machine.get_inserted_coins() - machine.get_item_price()
            if change > 0:
                print(f"Returning change: ₹{change}")
            machine.set_inserted_coins(0)
            print("Item selected. Dispensing now...")
            return machine.get_dispense_state()
        else:
            needed = machine.get_item_price() - machine.get_inserted_coins()
            print(f"Insufficient funds. Need ₹{needed} more.")
            return machine.get_has_coin_state()

    def dispense(self, machine: VendingMachine) -> VendingMachineState:
        print("Please select an item first.")
        return machine.get_has_coin_state()

    def return_coin(self, machine: VendingMachine) -> VendingMachineState:
        print(f"Returning ₹{machine.get_inserted_coins()} to user.")
        machine.set_inserted_coins(0)
        return machine.get_no_coin_state()

    def refill(self, machine: VendingMachine, quantity: int) -> VendingMachineState:
        print("Cannot refill while a transaction is in progress.")
        return machine.get_has_coin_state()

    def get_state_name(self) -> str:
        return "Has Coin State"


# ─── Concrete State: Dispense ───────────────────────────────────────────────────

class DispenseState(VendingMachineState):

    def insert_coin(self, machine: VendingMachine, coin: int) -> VendingMachineState:
        print("Please wait. Already dispensing an item.")
        return machine.get_dispense_state()

    def select_item(self, machine: VendingMachine) -> VendingMachineState:
        print("Already dispensing. Please wait.")
        return machine.get_dispense_state()

    def dispense(self, machine: VendingMachine) -> VendingMachineState:
        print("Item dispensed!")
        machine.decrement_item_count()
        if machine.get_item_count() > 0:
            return machine.get_no_coin_state()
        else:
            print("Machine is now sold out.")
            return machine.get_sold_out_state()

    def return_coin(self, machine: VendingMachine) -> VendingMachineState:
        print("Cannot return coin. Item is already being dispensed.")
        return machine.get_dispense_state()

    def refill(self, machine: VendingMachine, quantity: int) -> VendingMachineState:
        print("Cannot refill while dispensing.")
        return machine.get_dispense_state()

    def get_state_name(self) -> str:
        return "Dispense State"


# ─── Concrete State: Sold Out ───────────────────────────────────────────────────

class SoldOutState(VendingMachineState):

    def insert_coin(self, machine: VendingMachine, coin: int) -> VendingMachineState:
        print("Machine is sold out. Cannot accept coins.")
        return machine.get_sold_out_state()

    def select_item(self, machine: VendingMachine) -> VendingMachineState:
        print("Machine is sold out. No items to select.")
        return machine.get_sold_out_state()

    def dispense(self, machine: VendingMachine) -> VendingMachineState:
        print("Machine is sold out. Nothing to dispense.")
        return machine.get_sold_out_state()

    def return_coin(self, machine: VendingMachine) -> VendingMachineState:
        print("No coin inserted. Nothing to return.")
        return machine.get_sold_out_state()

    def refill(self, machine: VendingMachine, quantity: int) -> VendingMachineState:
        print(f"Refilling machine with {quantity} items.")
        machine.increment_item_count(quantity)
        return machine.get_no_coin_state()

    def get_state_name(self) -> str:
        return "Sold Out State"
```

## Standard UML (Generic Pattern)

```
┌───────────────────────────┐
│         Context           │
│───────────────────────────│
│ - state: State            │
│───────────────────────────│
│ + request()               │──── delegates ────►  state.handle(self)
└───────────────────────────┘


┌──────────────────┐
│      State       │  ← Abstract
│──────────────────│
│ + handle(ctx)    │  returns State
└────────┬─────────┘
         │
    ┌────┴────┐
    ▼         ▼
┌────────┐ ┌────────┐
│Concrete│ │Concrete│
│State A │ │State B │
│────────│ │────────│
│handle()│ │handle()│
└────────┘ └────────┘
  returns     returns
  State B     State A
  reference   reference
```

The context holds a `state` reference. Every method on the context just calls the corresponding method on `state`. Each concrete state's method returns a state reference (could be itself or another state), which the context stores as its new `current_state`.

---

## Standard Definition

> **State Design Pattern** allows an object to alter its behaviour when its internal state changes. The object will appear to change its class.

The client feels like the object's class is changing because the same method produces different results in different states. What's actually happening is that the internal state reference is being swapped, and each concrete state handles the method differently.

**Without this pattern**, you'd write this inside the vending machine class:

```python
def insert_coin(self, coin):
    if self.current_state == "no_coin":
        # handle no coin logic
    elif self.current_state == "has_coin":
        # handle has coin logic
    elif self.current_state == "dispense":
        # handle dispense logic
    elif self.current_state == "sold_out":
        # handle sold out logic
```

Multiply this by 5 methods and 4 states and you have 20 if-else blocks crammed into one class. Every new state means editing every single method. The State pattern eliminates all of that.

## Real World Use Cases

**Where do you apply State Design Pattern?** Any problem with a limited number of states and a limited number of operations on those states.

- **Vending Machine** — exactly what we built. A standard interview question; solve it directly with this pattern.

- **Document Editor / Publishing Platform** — a document on a platform like GFG can be in Draft state, Published state, Archived state, or Deleted state. Different operations are allowed in each state. Moving from Published → Archived is one state transition; Archived → Deleted is another.

- **ATM Machine** — we previously used Chain of Responsibility for the cash dispenser. But the ATM machine itself has states: Idle → Card Inserted → PIN Validation → Transaction → Dispensing. Each state allows different operations.
