# Remove Duplicates from Sorted Array

**Pattern:** Two Pointer · **Difficulty:** Easy · **LeetCode:** Remove Duplicates from Sorted Array

---

## Problem
Given a **sorted** array with possible duplicates, remove duplicates **in-place** (no extra space) so unique elements occupy the front of the array, in order. Return the **count of unique elements**.

---

## Recognition Signals
- [x] Array or Linked List? → Array
- [x] Sorted / sortable? → Given sorted
- [x] Keyword match? → "remove duplicates" (exact match)
- [x] Space constraint? → "in-place / no extra space"

All 4 signals match → Two Pointer near-guaranteed.

---

## Core Idea
Two pointers: a **slow pointer** (`officer`) marks the last confirmed unique slot; a **fast pointer** (`cm`) scans ahead. Since the array is sorted, duplicates are always adjacent — one comparison (`arr[i] == arr[i-1]`) is enough to detect them.

---

## Key Notes
- **Why the 1st element needs no check:** there's nothing before index 0 to compare against, so it's unique by definition — start `uniqueCount` at 1, not 0.
- **Why overwrite instead of swap:** everything past the unique-count boundary is discarded/irrelevant to the final answer, so there's no need to preserve it — just write over it directly.
- **Single-pass justification:** `cm` never revisits an index and `officer` only ever moves forward within the range `cm` has already covered — this is what keeps it O(n) instead of O(n²) (no nested re-scanning).
- Same officer/scanner logic transfers directly to **Remove Duplicates from Sorted Linked List** — only pointer mechanics (next-pointer vs index) differ.

---

## Approach Comparison

| Approach | Time | Space | Verdict |
|---|---|---|---|
| Bucket by value (group each type separately) | O(n) | O(n) | Fails "no extra space" |
| Two Pointer ⭐ | O(n) | O(1) | Optimal, meets constraint |

---

## Algorithm Steps
1. First element is always unique → `officer = 0`, `uniqueCount = 1`.
2. `cm = 1`.
3. While `cm < n`:
   - If `arr[cm] == arr[cm-1]` → duplicate, `cm++`, continue.
   - Else → unique: `arr[officer+1] = arr[cm]`, `officer++`, `uniqueCount++`, `cm++`.
4. Return `uniqueCount`.

---

## Pseudocode
```
function removeDuplicates(arr):
    n = length(arr)
    officer = 0
    uniqueCount = 1
    cm = 1
    while cm < n:
        if arr[cm] == arr[cm - 1]:
            cm++
            continue
        arr[officer + 1] = arr[cm]
        officer++
        uniqueCount++
        cm++
    return uniqueCount
```

---

## Dry Run
`arr = [1, 1, 2, 3]`

| cm | arr[cm] vs arr[cm-1] | Action | officer | count |
|---|---|---|---|---|
| init | — | officer=0, count=1 | 0 | 1 |
| 1 | 1 == 1 | duplicate, skip | 0 | 1 |
| 2 | 2 != 1 | place at officer+1=1, officer++ | 1 | 2 |
| 3 | 3 != 2 | place at officer+1=2, officer++ | 2 | 3 |

Final array front: `[1, 2, 3]` → return `3`

---

## Gotchas / Edge Cases
- `cm` **always** advances, every iteration, regardless of outcome.
- `officer` advances **only** when a new unique value is placed.
- No swapping needed — overwrite only, since content beyond `uniqueCount` doesn't matter.
- Same exact logic applies to **Remove Duplicates from Sorted Linked List** — only the traversal mechanics change.

---

## One-Line Recall
**Fast pointer scans for the next unique value; slow pointer marks where to drop it — sorted order makes "duplicate" a simple adjacent-equality check.**
